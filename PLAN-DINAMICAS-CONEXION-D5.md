# Juegos bíblicos para la web de Misión Juvenil D5

Propuesta inicial para una sección independiente de la página web. No forma parte de Conexión D5 ni depende de LiveKit. Puede construirse con Vanilla JavaScript y contenido local; más adelante se puede elegir otra tecnología si una función lo necesita.

Los juegos son voluntarios, ayudan a aprender de la Biblia y no requieren cámara, micrófono ni una reunión en vivo.

## Primera dinámica recomendada: Reto bíblico colaborativo

- La persona elige un tema o pasaje e inicia una partida individual o por equipos.
- Las respuestas se realizan en la propia página del juego.
- Cada pregunta muestra su referencia bíblica al cerrar la ronda, para que el grupo pueda leer el contexto.
- La página revela la respuesta y la referencia bíblica al cerrar cada pregunta.
- El marcador se conserva solo durante la partida, a menos que más adelante se apruebe guardar resultados.

## Otras actividades

1. **Ordena el pasaje:** el grupo acomoda frases de un versículo y luego consulta su referencia.
2. **¿Quién soy?:** se dan pistas progresivas sobre personajes o relatos bíblicos; se puede responder por chat o por equipos.
3. **Una palabra para llevar:** cada persona comparte, de forma opcional, una palabra o aprendizaje del devocional; no hay puntajes ni clasificación.

## Reglas de experiencia

- El anfitrión y los moderadores controlan el inicio, la pausa y el cierre.
- Siempre hay opción de observar sin participar.
- No hay castigos, apuestas ni exposición pública de quien no responde.
- Las respuestas no se presentan como asesoría pastoral, médica o psicológica.
- Las citas y preguntas deben revisarse con el equipo pastoral antes de publicar la actividad.

## Encaje técnico

La primera versión puede ser estática y ejecutarse en el navegador: HTML, CSS y Vanilla JavaScript, con preguntas y referencias en archivos locales. Esto evita añadir servicios, cuentas o costos recurrentes para probar el concepto. Si más adelante se necesitan partidas sincronizadas entre varias personas, se puede diseñar esa capacidad por separado; no es un requisito para el primer juego.
